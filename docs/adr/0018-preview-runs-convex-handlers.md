# ADR 0018: Preview mode runs the real Convex handlers in the browser

- **Date:** 2026-10-13
- **Status:** accepted (refines ADR 0010)

## Context
ADR 0010 keeps OSCURA's preview mode: without `NEXT_PUBLIC_CONVEX_URL` the app runs on demo handlers, one per Convex function, sharing the pure rules in `lib/domain/`. In OSCURA that meant a second hand-written backend (`lib/demo/handlers.ts`, 834 lines) that drifted from `convex/` and needed its own fixes. The First has about 120 functions; a parallel copy would double the backend work and its bugs.

## Decision
Preview mode executes the registered Convex functions themselves. `lib/demo/db.ts` implements the part of `ctx.db` the backend uses (get, insert, patch, replace, delete, normalizeId, indexed queries with ranges, filters, order, take, first, unique, collect, paginate) over plain arrays, reading index fields from `convex/schema.ts`. `lib/demo/engine.ts` builds `ctx` (db, auth from the demo session subject, storage with data URLs, scheduler that re-runs scheduled mutations with timers) and calls each function's handler. Mutations run on a copy of the state and only commit if they return, like a Convex transaction. `lib/demo/registry.ts` is generated by `scripts/gen-convex-api.mjs` with `convex/_generated/api.d.ts`; Node actions (`"use node"`) are skipped. The demo database is seeded by the real `seed:demo` mutation and persisted in `localStorage`, synced across tabs. Bridge mutations accept a per-tab secret set by the engine only in the browser (`__TF_PREVIEW_BRIDGE__`); on Convex only the `AUTH_BRIDGE_SECRET` env var exists.

The same engine is the backend test harness (`tests/support/engine.ts`): every function is tested with the demo seed, signed in as a real demo person, including the role × function × venue matrix.

Project rule 12 ("every Convex function used by the UI has a handler in `lib/demo/handlers.ts`") is satisfied by construction: the registry lists every module.

## Alternatives considered
| Option | For | Against |
|---|---|---|
| Hand-written demo handlers (OSCURA) | Small bundle | Two backends, drift, double tests |
| convex-test in the browser | Official semantics | Built for Vitest; state not serializable with stable ids |
| Always a Convex dev deployment | Real backend | Needs keys and network for every preview (ADR 0010 rejected it) |

## Consequences
- Argument validators are not run in preview (handlers still validate with Zod through `parseOrThrow`); Convex runs both in production.
- The engine bundles the Convex modules, so it is loaded with a dynamic import only in preview mode (`lib/demo/load.ts`) and never enters a production route's first load.
- Crons do not run in preview; scheduled mutations (request escalation at 90 s) do.
