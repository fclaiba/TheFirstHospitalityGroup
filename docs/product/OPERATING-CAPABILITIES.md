## Current implementation contract: role enablement

Learners use a daily role playbook and request review against primary/next-role published criteria. Supervisors review only a trained position below them in the configured venue chain, never themselves or peers. States are not started, ready for review, needs practice and verified. Reviews require an observed demonstration or a concrete practice instruction; a new request preserves the previous event. Program versions are immutable, and stale or competing reviews fail. Old evidence remains available; a new version starts new criteria. No automatic promotion, role enabling or discipline occurs.

Interfaces: `training.mine`, `training.requestReview`, `training.queue` (paginated), `training.review`, `training.history` (paginated), `training.program`, `training.publish`. Additive tables: `trainingPrograms`, `trainingRecords`, `trainingEvents`; each write is audited. Programs and criteria require EN/ES. Own evidence is private to the learner and authorized chain. Owner playbook has governance actions without self-certification. Default programs work without destructive reseeding; authorized corporate leaders can publish company-specific replacements.
