# Operating UX audit

The goal is fast, understandable execution and accountable supervision for every role. The user's request for a substantially better UX and interactive guides extends, rather than replaces, the full operating objective and the instruction to complete the blueprint and push to main. No claim of perfect usability follows from automated checks.

| Observed problem | Consequence | Required improvement and evidence |
|---|---|---|
| Help is a text block with an optional link | People must mentally translate instructions into controls | Voluntary walkthrough spotlights the actual control; Previous/Next/Exit; all route and role families, keyboard, mobile, Large text and axe |
| Close items were plain notes | No accountable next action | Durable assignment, due time, resolution evidence and independent verification; seven handler tests and six browser scenarios now pass |
| Encoded preview IDs did not open a just-created action | A successful save led to Not found | Decode the route identifier; browser round trip including reload now passes |
| Corporate venue follow-up opens an own-work queue first | Director may mistake an empty queue for an empty venue | Default supervisors to supervised work, preserve an explicit own-work choice and selected venue |
| The shared Today preview imports the complete action editor module | Today JS increased to 156.8 KB gzip | Split the small read-only preview from editors and lazy-load walkthrough internals; preserve the 170 KB staff budget |
| Archived training exists but supervisors cannot browse completed evidence by person | A supervisor cannot fully assess readiness without a pending request | Discoverable private learning record per person and program version, with chain checks |
| Reporting overrides can form a cycle | Ambiguous authority affects review and escalation | Validate the entire configured chain before writing, not just self-links |
| Some no-venue paths remain loading skeletons | New or deactivated assignments offer no next step | Explicit no-active-venue recovery state on every module; role and first-run journeys |
| No representative-user task study has run | Age-spanning usability remains unverified | Blueprint section 15 moderated tasks, real-device checks and measured completion; never replace with screenshot approval |

Walkthroughs must not activate the highlighted business control, send a request, publish, acknowledge or write data. Missing or disabled controls must not be described as available. Loaded content, empty, offline, error and locked states need useful explanations. Urgent help remains separate from ordinary operational follow-up. Owner/director actions must lead to a named accountable leader, not just a colored dashboard.

Before main integration: inspect the current remote, avoid overwriting other work, run the repository gates and green CI, retain frontend/browser-mock scope, and avoid triggering an unrequested remote Convex deployment. The user authorized a main push; credentials, real venue content, live legal policy and moderated-user evidence cannot be invented.

## Verified walkthrough increment

Local regression: 129 scenarios passed in 5.5 minutes on Pixel 7, 375 px iPhone SE emulation and desktop 1440. Guides complete on all 51 registered operational route entries, public/role families and four actual linked detail families. The generic sheet primitive now exposes a scoped guide; request-kind and table-selection states were exercised with preserved selection, unchanged preview records, native-dialog keyboard containment and focus restoration. Other sheet types share this primitive and their existing operational regression, but a distinct guided task study for each remains useful.

The real highlighted target remains sharp inside four surrounding blur panels. Previous, Next, Finish, Exit and Escape work without activating the underlying control. Ancestor and work-viewport scrolling are restored. Large text in English no longer overlaps Request and Interactive guide at 375 px. Failed lazy guide downloads have translated retry/close recovery. The shared shell separates work scrolling from header/navigation, and publishing a training version focuses the new-version confirmation. Encoded identifiers now open menu, announcement, venue and person details from actual links and after reload.

Technical evidence: 274 unit/handler tests, zero lint/type errors, 71 generated pages, 21/21 route budgets and zero production dependency vulnerabilities. No serious/critical axe violations occurred in checked journeys. These results do not establish perfect usability or age-spanning task success. Guides currently explain visible semantic controls and route purposes; representative operators must validate task-specific wording, sequencing and recovery in real service conditions.

PR: https://github.com/fclaiba/TheFirstHospitalityGroup/pull/1. First CI run revealed missing generated Next route types on a clean install; the corrected command generates them before TypeScript. Quality and backend validation passed on the corrected head; remote browser/Lighthouse and authenticated preview review remain pending at this entry. Vercel preview exists but redirects to Vercel SSO without an authenticated session. No remote backend functions were deployed. Vercel builds and main CI no longer deploy Convex implicitly.

Remaining concrete work includes the supervised default for corporate action queues and explicit venue context on action details, discoverable completed training per person, chain-cycle validation, first-run/no-active-venue recovery and the full operator task audit listed above. None is waived by adding tours.
